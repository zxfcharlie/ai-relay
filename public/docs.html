这台服务对外提供一个 OpenAI 兼容的中转接口：用你自己的中转密钥代替真实的 OpenAI / Claude 密钥， 任何支持自定义 base_url 的 OpenAI SDK 或第三方工具都可以直接指向这里。 密钥在「设置 → 中转访问」里可以查看和重新生成。

鉴权

所有 /v1/* 接口都需要在请求头里带上你的中转密钥：

Authorization: Bearer rk-你的中转密钥

密钥缺失或错误会返回 401。这个密钥和你的登录密码无关，是每个账号独立生成、可随时重置的，重置后旧密钥立即失效。

Base URL

/v1

下面示例里的 <base_url> 都指这个地址。

GET /v1/models

返回当前账号（根据配置的密钥）在 OpenAI / Claude 上实时可用的全部模型，除标准的 OpenAI 模型字段外， 额外带了三个自定义字段，方便你自己的客户端也做分类和搜索：

字段说明
id模型 ID，直接用于其他接口的 model 参数
owned_byopenai 或 claude
categorychat（对话/视觉）或 image（图像生成）
tierflagship / reasoning / fast / balanced / image
description一句中文简介
 
curl <base_url>/models \
  -H "Authorization: Bearer rk-你的中转密钥"

POST /v1/chat/completions

对话接口，OpenAI 请求/响应格式进出，实际按 model 自动路由到 OpenAI 或 Claude，流式响应也统一是 OpenAI 的 SSE 格式。

字段说明
model必填，模型 ID
messages必填，标准 OpenAI 消息数组；content 支持字符串，或数组形式的多模态内容：{type:"text",...}、{type:"image_url",image_url:{url:"data:..."}}（图片）、{type:"file",file:{file_data:"data:application/pdf;base64,...",filename:"..."}}（PDF，标准 OpenAI Chat Completions 格式），都会按目标模型自动转换成对应厂商需要的格式（比如 PDF 会转成 Claude 的 document 内容块）
stream选填，布尔，默认 false
provider选填，"openai" / "claude" / 管理员在后台加的第三方服务商标识，显式覆盖按模型名自动判断的路由（第三方模型名一般猜不出来源，建议总是显式传）
未识别的模型名如果没有显式传 provider，会返回 400。temperature/max_tokens 等采样参数目前不会透传给上游，统一使用各模型的默认值。非流式响应里的 usage 字段是占位的 0，不代表真实 token 消耗。
curl <base_url>/chat/completions \
  -H "Authorization: Bearer rk-你的中转密钥" \
  -H "Content-Type: application/json" \
  -d '{
        "model": "claude-sonnet-4-6",
        "messages": [{"role": "user", "content": "Hello"}],
        "stream": false
      }'
from openai import OpenAI

client = OpenAI(base_url="<base_url>", api_key="rk-你的中转密钥")

resp = client.chat.completions.create(
    model="gpt-5.1",
    messages=[{"role": "user", "content": "Hello"}],
    stream=True,
)
for chunk in resp:
    if chunk.choices[0].delta.content:
        print(chunk.choices[0].delta.content, end="")
import OpenAI from "openai";

const client = new OpenAI({ baseURL: "<base_url>", apiKey: "rk-你的中转密钥" });

const stream = await client.chat.completions.create({
  model: "claude-sonnet-4-6",
  messages: [{ role: "user", content: "Hello" }],
  stream: true,
});
for await (const chunk of stream) {
  process.stdout.write(chunk.choices[0]?.delta?.content || "");
}

POST /v1/images/generations

文生图，对应官方 SDK 的 client.images.generate()。只支持 OpenAI 的 gpt-image-* 系列（Claude 没有生图接口）。

字段说明
model必填，例如 gpt-image-2
prompt必填，图片描述
size选填，"auto" 或 "宽x高"（如 "1024x1024"）；gpt-image-2 及更新的模型支持任意分辨率
quality选填，auto / low / medium / high / xhigh / max —— 影响费用最主要的参数
n选填，生成数量，1–10，默认 1
output_format选填，png / jpeg / webp，默认 png
background选填，auto / opaque / transparent
响应始终是 {"data": [{"b64_json": "..."}]}——GPT Image 系列不接受 response_format，传了会被 OpenAI 直接拒绝，所以这里也不支持传这个字段，固定返回 base64。
curl <base_url>/images/generations \
  -H "Authorization: Bearer rk-你的中转密钥" \
  -H "Content-Type: application/json" \
  -d '{
        "model": "gpt-image-2",
        "prompt": "一只戴墨镜的柴犬，插画风格",
        "size": "1024x1024",
        "quality": "low",
        "n": 1
      }'
from openai import OpenAI
import base64

client = OpenAI(base_url="<base_url>", api_key="rk-你的中转密钥")

resp = client.images.generate(
    model="gpt-image-2",
    prompt="一只戴墨镜的柴犬，插画风格",
    size="1024x1024",
    quality="low",
)
with open("out.png", "wb") as f:
    f.write(base64.b64decode(resp.data[0].b64_json))

POST /v1/images/edits

图片编辑（改色、换背景、合成参考图等），对应官方 SDK 的 client.images.edit()。multipart/form-data 请求。

字段说明
model必填
prompt必填，编辑指令
image / image[]必填，一张用 image，多张参考图重复使用 image[] 字段（最多 16 张）
size / quality / n / output_format / background选填，同 /images/generations
 
curl <base_url>/images/edits \
  -H "Authorization: Bearer rk-你的中转密钥" \
  -F "model=gpt-image-2" \
  -F "prompt=把包的颜色改成黑色" \
  -F "quality=medium" \
  -F "image[]=@bag.png"
from openai import OpenAI
import base64

client = OpenAI(base_url="<base_url>", api_key="rk-你的中转密钥")

resp = client.images.edit(
    model="gpt-image-2",
    prompt="把包的颜色改成黑色",
    image=open("bag.png", "rb"),
    quality="medium",
)
with open("out.png", "wb") as f:
    f.write(base64.b64decode(resp.data[0].b64_json))

错误格式

失败时统一返回：

{
  "error": {
    "message": "具体错误信息",
    "type": "invalid_request_error"
  }
}
type对应场景
authentication_error中转密钥缺失或不正确（401）
invalid_request_error请求缺字段、模型无法识别、没配置对应服务商密钥等（400）
api_error上游 OpenAI / Claude 调用失败，message 里是上游返回的原始错误（502）

流式响应里的错误会作为最后一个 data: 事件发出（同样是上面这个结构），随后紧跟 data: [DONE]。
